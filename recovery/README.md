# YTLite 5.2.2 source recovery

This directory contains a buildable Objective-C reconstruction from the three supplied 5.2.2 packages. All 51 first-party classes and 446 selected registration records have source implementations. Twenty authentication, attestation, app-origin verification and permission bypass records remain evidence-only exclusions. Historical account activation and integrity/bootstrap effects are also omitted under the existing local preference policy. This is not an exact restoration of every packaged behavior.

## Current source status

The latest `recovery/tools/source_inventory.py` run compiled **61 selected Objective-C files for iOS arm64**. They implement **all 51 first-party classes**, with all **864 packaged method signatures** matching. This checks implementation presence and ABI; it does not prove behavior or feature integration. The per-class results and source hashes are in [evidence/source-inventory.json](evidence/source-inventory.json). A separate [category inventory](evidence/category-source-inventory.json) matches all three packaged Objective-C categories and their six methods.

| Source directory | Reconstructed systems |
| --- | --- |
| `source/Models`, `source/Support` | Settings and media models, segment models, database tables, default values and colors |
| `Utils` in the repository root | Preferences, SponsorBlock IDs, settings import/export, bundle lookup and localization |
| `source/Downloads` | Download menus, API helper, downloader, media preparation, audio handling and FFmpeg calls |
| `source/Settings` | Settings builder, table controllers/cells, pickers, tab configuration and supporters |
| `source/Playback`, `source/Subtitles` | SponsorBlock managers/decorators, SRT parsing, translation and translator UI |

| `source/Media` | Photos video selection, startup-animation installation and local file import |
| `source/SleepTimer` | Presets, time-of-day and end-of-video modes, countdown, volume fade and status-bar actions |

`source/recovered.mk` selects the canonical implementations. Root-level `Recovered/` model copies and `source/Playback/SRTParser.m` are superseded independent reconstructions and excluded from the build. The canonical parser is `source/Subtitles/SRTParser.m`.

The hook modules contain the recovered playback, feed, settings, sharing, navigation and compatibility behavior. Root hook files now delegate to those modules. Existing local-fork changes use local feature preferences and exclude the historical account bootstrap. The old backup hooks and receipt-based sideload initializer have been replaced; retirement evidence records their hashes and retained local backup paths.

## Build and integration checks

The complete Theos build compiles, links, generates debug symbols and signs a new arm64 dylib. The standalone FFmpeg dependency has been rebuilt from pinned upstream source. Its seven Objective-C classes match the original library's 74 methods and 24 ivars, and its build configuration matches the packaged feature flags. SDK and dependency-version differences are documented in `dependencies/ffmpeg/`. The original combined tweak binary is not a build input or substitute library.

All selected hook modules install through `source/Runtime/YTLHookEntrypoints.m`. The recovered startup includes the identity-based compatibility predicate, immediate and deferred hook phases, welcome scheduling, SponsorBlock ID initialization and saved language-index repair. Module grouping preserves overlapping replacement chains but does not replay every registrar instruction in exact order. The original account-dependent queue release time is not reproduced.

The independent original-instruction scan accounts for 466 direct registration sites. Of these, 446 have selected owners and 20 are explicit exclusions. This includes 25 sites missed by the initial decompiler extractor. The [integration report](evidence/integration-verification.json) ties selected ownership to the current linked artifact and source hashes; counts include alternative registration paths and dynamic aliases, not 446 distinct features.

Focused fixtures execute actual reconstructed implementations through the Objective-C runtime with synthetic host objects. Recent suites include 3,337 general-interface checks, 2,299 player-control checks, 4,762 presentation/helper checks, 1,383 playback-options checks, 1,335 sideload-identity checks and 387 startup checks. These test forwarding, branches, block lifetime and selected property metadata. They do not establish behavior inside the real YouTube app.

The packaged asset catalog is now deployed, with all 161 asset names. The three packages have identical resource files. Existing locale edits remain in the working copy; [resource evidence](evidence/deployed-resources.json) records their differences from the packages.

Build output and logs are under `.recovery-work/build/` and `.theos/obj/`. The package adapter now supports this ExFAT checkout by preparing a temporary copy with Debian-compatible permissions. Its tests reproduce the prior `0700` control-directory rejection and check the resulting archive; see [package construction](build/roothide/README.md). No original package has been installed or executed, and no on-device validation is claimed.

## Binary evidence

At baseline commit `e8bb26f`, `Makefile` labels the backup `3.0.1`; the last original `YTLite.x` change is `e5894e7`, dated March 10, 2024. Later version labels, assets and translations do not establish an implementation baseline. Recovery therefore compares actual source and packaged behavior rather than assuming only a small 5.2b4-to-5.2.2 change.

| Path | Contents |
| --- | --- |

| `classes/`, `hooks/`, `decompiled/` | Pseudocode evidence, including 3,211 individual exports; these `.c` files are not buildable source |
| `evidence/hooks.json` | 441 registrations: 438 mapped to class, selector and implementation; three unresolved |

| `evidence/packages.json`, `resources/` | Input hashes and exact packaged resource bundles for all three variants |

All 864 methods in the 51 first-party classes and all mapped hook implementations have decompiler exports. An export alone is not a correct source reconstruction: unresolved control flow, ARC, block captures and argument types require instruction-level review. The initial export coverage report records 353 functions with analysis warnings or unresolved register inputs; later focused analysis is retained separately under `.recovery-work/`.

The three package binaries have equal recovered class metadata and decoded-string multisets, despite different binary hashes and installation layouts. All contain ARM64 Mach-O images; their Debian architecture labels do not represent three independent source snapshots. Original comments, local variable names, macros, filenames and formatting generally cannot be recovered exactly.

The supplied packages were not executed or installed. See [REPRODUCE.md](REPRODUCE.md) for the extraction and verification commands.
