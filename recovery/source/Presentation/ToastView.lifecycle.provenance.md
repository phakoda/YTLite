# ToastView lifecycle fidelity

This pass recovers ordinary command and dismissal behavior from the supplied arm package. `recovery/evidence/toast-lifecycle-fidelity.json` pins all 58 original functions from `0x1bfdd0` through `0x1c2e20`, nine additional shared capture helpers, all 14 indirect branches, twelve block descriptors, imported wrapper destinations, and the numeric instruction words. The binary SHA is checked against the package inventory. Assembly text is compared instruction by instruction with raw executable bytes.

The eight command implementations at `0x1bffdc`, `0x1c0468`, `0x1c0740`, `0x1c09b0`, `0x1c0ccc`, `0x1c0f78`, `0x1c1680`, and `0x1c1af8` capture their receiver strongly. The copy helpers load receiver offset `+0x20` and call `_objc_retain`; no weak-object helper is used. Their nested display and action callbacks retain their captured objects too. Progress and icon callbacks `0x1c02b0` and `0x1c1a6c` only assign the completion property when the captured completion is nonnil. The title action callback `0x1c1544` invokes the supplied action, then hides its captured toast. The wait-style callback `0x1c0bf4` schedules `0x1c0c84` after 0.5 seconds to clear `_isAnimating` and process the queue. Ordinary text and default status messages hide after 2.5 seconds; donation countdown is 10 seconds. All eight display callbacks calculate geometry before reading the current `_widthConstraint.constant`; the prior helper evaluated width before calculation. A fixture that replaces the constraint during calculation failed before this correction and now observes its replacement width.

`cancelButtonTapped` (`0x1bfdd0`) reads the completion getter once for its condition and again for invocation. It reads the ignores-pan ivar after invoking completion. `handleLongPress:` (`0x1bff34`) hides only on state 1. The two update methods (`0x1c033c`, `0x1c03b4`) write the label and progress directly; the shorter overload does not dispatch through the longer one.

`startTimerCountdown:` (`0x1c1d18`) creates a repeating 0.016-second local timer and adds it to the main run loop in common modes. It does not read, invalidate, or write `_progressTimer`. The timer block (`0x1c1e4c`) retains the toast and a byref double initialized to 1. Each tick subtracts `0.016 / duration`. Raw `FCMP d0,#0` at `0x1c1e9c` followed by `CSET HI` at `0x1c1ea0` routes positive **and unordered NaN** values to the animated progress update. Ordered zero or negative values set progress to zero, invalidate the callback's timer, and hide. The source uses `!(remaining <= 0)` because the decompiler's `remaining > 0` loses the unordered case. Positive-zero duration therefore hides on its first tick; negative zero writes positive-infinite progress, negative duration increases progress, either infinity preserves 1, and NaN remains scheduled with NaN progress.

`hideAnimatedWithCompletion:` (`0x1c1fb4`) removes layer animations, applies scale 1→0.8 and opacity 1→0 over 0.3 seconds with ease-in timing, and commits the final layer transform/opacity. It does not invalidate a timer or set `_isAnimating` on entry. Transaction completion `0x1c269c` clears `_isAnimating`, then invokes the provided completion or runs cleanup followed by queue processing. `hideImmediately` (`0x1c2760`) directly runs cleanup and queue processing without alpha/state resets or thread dispatch.

`hideWithDelay:` (`0x1c27b0`) multiplies its double delay by 1e9 and converts with raw `FCVTZS x1,d0` (`0x1c27d0`). The portable source explicitly preserves signed saturation and NaN-to-zero conversion. Its strongly capturing callback `0x1c282c` directly invokes `hideAnimatedWithCompletion:nil`; it has no reuse-generation guard. `hide` delegates with delay zero. `isHidden` (`0x1c2878`) returns the superclass result and schedules the global callback `0x1c28e0` after 0.3 seconds; that callback calls `ToastManager.updateAllToasts`. `hideWithCompletion:` (`0x1c2944`) invokes a supplied completion synchronously when already idle/transparent, does nothing in that state for nil, and otherwise dispatches animated hide to the main queue. The remaining orientation/fullscreen/pinned/offset getters and completion property preserve their original ABI. `dealloc` (`0x1c2d78`) removes observers without invalidating `_progressTimer`.

Parent-audited construction changes in the same file restore direct initialize/queue calls, window dispatch-once consumption even without a scene, active-scene/fallback selection, the deferred make-key-and-visible call before constraint activation, cached source views, the original iPad predicate before super initialization, setup reuse without invented state resets, and cleanup without completion/generation resets. Observer methods use three fresh notification-center reads, and notification callbacks update synchronously. Both configure methods set bottom/width/top in that order. The non-alpha animation sets transform before reading pinned state; the alpha variant neither changes hidden nor calls layoutIfNeeded. The parent's separate construction fixture owns those branch checks.

Run `python3 recovery/tools/verify_toast_lifecycle.py`. It compiles the complete production source against unique synthetic UIKit/timer/dispatch boundaries under UBSan, checks all 47 iOS method encodings plus the property and relative ivar layout, and runs command variants, nil/non-nil callbacks, state branches, exceptional numeric values, background direct updates, and retention/release tests. Nine isolated source mutations reintroduce the previous mismatches and must fail the actual-source fixture. The original packaged executable is never executed and there are no real app/network operations.

Original supervisor-call anti-debug effects and obfuscation state are recorded but omitted. The runtime fixture establishes observable source behavior at intercepted boundaries, not UIKit rendering on a physical iPhone or byte-identical recompilation. Original strong ownership and stale delayed dismissals are intentional fidelity here, including their original retention/reuse consequences.
