# Sheet lifecycle fidelity correction

This pass covers all 22 original methods of `PseudoDetentController` (13), `PseudoDetentTransitioningDelegate` (6), and `DVNSheetPresenter` (3), six anonymous UI/height callbacks, the section-height helper and the strong-capture copy/dispose helpers. `SheetLifecycle.evidence.json` pins their 31 raw original intervals and seven resolved branch tables against the supplied arm image SHA-256 `bdcc4d4ccaa5835d35bc97ccbdfc1c3dff514cb7161848265dcc0585f364c0ca`. Instruction and descriptor checks use raw image bytes; the decoded-byte overlay is used only for encoded strings and branch-table keys.

## Confirmed corrections

- **Strong transition captures.** Presentation animation `0x1f1554`, dismissal animation `0x1f1698`, and dismissal completion `0x1f16e0` load their captured owner directly from block offset 32. The original flags are `0xc2000000`, descriptor `0x1062f00` has size 40, copy helper `0x150e8` calls `objc_retain` on the object at offset 32, and dispose helper `0x15118` calls `objc_release`. Its strong-layout value is `0x100`. These are strong object captures, not weak captures. The restored blocks use `self` directly.
- **No nil-coordinator fallback.** The original methods call `animateAlongsideTransition:completion:` at `0x1f1510` and `0x1f1660` without testing the coordinator or its Boolean return. A nil coordinator leaves the current alpha and hierarchy unchanged after the presentation method's synchronous setup. The previous immediate fade/removal fallback was invented.
- **Unconditional dismissal removal.** Completion `0x1f16e0` only retrieves `dimmingView` and calls `removeFromSuperview` at `0x1f1710`. It never reads the context's cancellation state. A cancelled dismissal therefore receives the same removal behavior. The previous shield-preservation branch was invented.
- **Layout and getter dispatch.** Initial construction calls `alloc`/`initWithFrame:CGRectZero`, then `setDimmingView:` and three `dimmingView` getter calls. Layout `0x1f118c` calls super, computes the presented frame, and sets only `presentedView.frame`; it does not resize dimming during subsequent layouts. Frame calculation reads `customHeight` at `0x1f10bc` even when a calculator exists, then checks `heightCalculator` at `0x1f10d4` and reads it again at `0x1f1130` before calling the second result with a CGSize. The delegate method gets/sets custom height at `0x1f1fec`/`0x1f1ffc`, followed by the calculator at `0x1f200c`/`0x1f202c`. Direct ivar reads and reversed forwarding had skipped these observable accessor calls. Presentation sets corner radius 15 both before and after `masksToBounds=YES`, then masked corners 3; the second original setter call is restored.
- **Delegate lifetime.** Each iOS 14 path creates a local `PseudoDetentTransitioningDelegate`, sets its calculator, assigns the controller's weak transitioning delegate, resets preferred content size, and presents. Original releases at `0x1eff14`, `0x1f0300`, and `0x1f067c` occur after the presentation call. There is no associated-object retention in these methods or their call wrappers. The new local uses `objc_precise_lifetime` to keep it alive through that call; it is no longer retained by a new controller association after return. The presentation controller owns its copied calculator independently.
- **Availability and half-height ordering.** All three native-sheet decisions call the platform version helper with `(2,15,0,0)`; that helper reaches `__availability_version_check`. There is no `respondsToSelector:` condition and no early return for nil controller/presenter parameters. Native sheets preserve the `dvntm` constant-height detent, grabber and radius 15. The half-screen method reads presenter view bounds only in its native branch, after acquiring the sheet controller. Its fallback calculator is a noncapturing global block at `0x1062ee0`, invoke `0x1f0350`; it uses half the container height in portrait/square/unordered cases and full container height when width is greater. Custom and explicit calculators capture a single double and implement the same orientation branch with that custom value.

The original transition block encoding is `v16@?0@"<UIViewControllerTransitionCoordinatorContext>"8`; calculator encoding is `d24@?0{CGSize=dd}8`. Runtime descriptors and compiled iOS IR are checked against both, including strong capture layout, 40-byte capturing blocks, and the 32-byte half-height global block. Compiler-generated property accessors, copy/strong destruction and the exact class/property/ivar ABI remain present.

## Verification

Run `python3 recovery/tools/verify_sheet_lifecycle.py`. It compiles the actual three sources with isolated host UIKit doubles and UndefinedBehaviorSanitizer, executes delayed callbacks, and runs the iOS source metadata audit. Only the presenter's `@available(iOS 15.0, *)` expression is replaced in a generated host copy with `SheetNativeAvailable()` so both OS branches can execute on the Mac. No method or callback logic is translated into the fixture.

The initial actual-source run produced 40 failures (`.recovery-work/sheet-lifecycle/red.txt`) covering the concrete differences above. The fixture checks dynamic getter order, failed initialization, recognizer forwarding, frame/alpha/corner/hierarchy state, delayed strong-owner lifetime for each of the three blocks, ignored cancellation/return value, nil coordinators, native detents, absence of a selector gate, lifetime through presentation and release afterward, nil-argument forwarding, section counts, and all three orientation calculators. Calculator cases include portrait, landscape, square, NaN, infinities and signed zero against a newly compiled native FCMP/FCSEL oracle. No original code is executed. Reports and logs are under `.recovery-work/sheet-lifecycle/` and `.recovery-work/ios-audit-sheet-lifecycle/`.

This restores ordinary UI behavior supported by the original bytes; it is not a claim that the original behavior is preferable UX. Actual UIKit animation scheduling and presentation integration remain device-level verification limits. Obfuscation/SVC scaffolding remains omitted. Authentication, permissions, network behavior and path validation were not modified. Shared presentation reports and old `TestSheets` expectations need regeneration by the integrating owner; this pass does not edit those shared files.
