# PlayerToast lifecycle fidelity

This bounded audit restores confirmed ordinary UI differences in `PlayerToast.m`. It preserves the separately verified FCVTAS percentage rounding and float NSNumber boxing. It does not change shared geometry helpers, other presentation classes, permission logic or any network/account behavior.

The original binary SHA-256 is `bdcc4d4ccaa5835d35bc97ccbdfc1c3dff514cb7161848265dcc0585f364c0ca`. `recovery/tests/player_toast_lifecycle_evidence.json` pins all 16 class methods and the relevant callbacks/copy helpers in 25 complete instruction spans, 15 key instruction words, two decoded branch tables and five constant/descriptor records. Only the reconstructed source runs in tests.

| Original method/callback | Confirmed behavior restored |
| --- | --- |
| `init` `0x23b560` | Creates blur effect style 5 before calling superclass initialization, then uses that effect for the material view. The previous source delayed effect creation until after other initialization. |
| `prepareForPresentation` `0x23c1e0` | Removes layer animations, removes the view from its superview, and sets alpha zero. The packaged method has no associated presentation-generation state. The added generation helper/key and writes were removed. |
| `showPlayerToastWithText:value:style:isCompact:` `0x23bd28` | Calls `sourceView` three times: for attachment, the safe-area top anchor, and the center anchor. The previous source cached one result and returned early if it was nil. It also forced `layoutIfNeeded` and assigned the material-view frame; neither operation appears in the original. Those additions were removed. The original activates constraints and schedules alpha-one animation at `0x23c1a4`, duration 0.3, delay zero, options `0x20000`, nil completion. |
| `hideToast` `0x23c67c`, animation `0x23c710`, completion `0x23c724` | Schedules alpha-zero animation with duration 0.3, delay one second, options `0x10000`. The completion only tests `finished`. Successful completion removes the view, then removes the current volume HUD from its controller. There is no generation comparison. An older successful completion can remove a newer presentation; a failed completion performs neither removal. |
| `sourceView` `0x23e19c` | Returns `UIApplication.sharedApplication.delegate.window` directly. The source previously used a shared helper with selector validation and a scene/key-window fallback. The method now keeps the original direct getter behavior. |
| `updateToastText:value:` `0x23c264` | Restores the initial image getter/setter self-assignment before progress/text/event updates. A changed image still schedules a 0.5-second transition, options `0x500000`, nil completion. Callback `0x23c4e8` writes its captured image to the toast's current `_toastImage`, including after that ivar has been replaced. Rounding and unrounded event/progress arguments remain unchanged. |
| `setProgress:` `0x23c52c` | The original first bounds read supplies width; the second supplies height after transaction setup. The source now preserves both reads. It applies FCSEL-GT followed by FMAXNM semantics locally: positive infinity clamps to one, negative infinity and NaN clamp to zero. The old shared finite-value helper incorrectly turned positive infinity into zero. The original width test is FP HI at `0x23c578`, so an unordered width still enters the transaction, matching the retained `width <= 0` early-return form. |

The previously unresolved hide table at `0x11d2890`, key `0x11d28a0`, XOR `0x896d7300`, resolves directly from original bytes. Entry zero is `0x23c7a4`, the return tail. Entry one is `0x23c774`, which reads controller capture offset 32, sends `removeFromSuperview` at `0x23c784`, then loads its current HUD and sends `removeFromController` at `0x23c7a0`. This is the evidence for removing the generation check while retaining the completion's `finished` condition.

Show/hide animation blocks use descriptor `0x1061420`; the hide completion uses `0x1061940`. Both descriptors have size 40 and helpers `0x150e8`/`0x15118`, which strongly retain/release the toast at offset 32. The icon transition descriptor `0x1061f70` has size 48 and helpers `0xc0fa8`/`0xbf16c`, which retain/release both toast and image at offsets 32/40. Runtime weak-reference probes isolate each retained animation/completion and the image payload. These confirm strong ownership and release when the final block goes away. No weak-capture substitution was introduced.

`python3 recovery/tools/verify_player_toast_lifecycle.py` checks the original evidence, audits iOS metadata, then compiles the complete `PlayerToast.m` with unique test-only UI, layer, HUD and scheduling doubles. It runs six fresh process modes for initialization, hiding, showing, source selection, progress and update/capture behavior, with UndefinedBehaviorSanitizer. The progress fixture compares against newly compiled native FCSEL/FMAXNM instructions, including infinities, NaN and signed zero. It also tests changing bounds between getter calls. The test-only UIKit doubles were copied into this fixture's own files so the shared presentation fixture remains untouched.

Before the correction, all five initial regression modes failed on their targeted difference, and a sixth initialization-order test also failed. The first five recorded failures are preserved in `.recovery-work/player-toast-lifecycle/red.json`; command output and current verification reports are in the same directory. No real brightness/volume changes, animations, presentation, network requests or preferences reads occur.

The nil-source test uses permissive constraint doubles to expose the original continuation and repeated getter calls. It does not promise that real UIKit accepts a nil anchor; UIKit may raise instead. Removing the invented early return restores that boundary behavior. This audit does not claim live-device appearance or a complete new proof of all icon thresholds/constraint constants; existing presentation tests retain those separate checks. Parent-owned shared provenance and manifests need to remove the PlayerToast generation-defense claim, and the old shared test expecting stale PlayerToast completion to preserve a new presentation must be inverted. The unrelated ToastView generation behavior is outside this change.
