# ToastView geometry fidelity

This pass covers `updateLayout` at `0x1be8a0` and `calculateToastParametersWithKeyboardHeight:bottomOffset:topOffset:scale:` at `0x1be9d8`. The unique evidence file `recovery/evidence/toast-geometry-fidelity.json` pins both complete function ranges, all 349 original instruction words, nine indirect branches, and critical scalar arithmetic/store instructions. The existing guarded `bottomOffset` host getter is unchanged.

Calculation reads source safe-area insets, manager/toasts, index, count, screen bounds width, and the first bottom-offset getter, in that order. There is no collection synchronization. It then writes scale 1 and safeTop+15 before reading the second bottom offset in the nonpositive/unordered keyboard branch. Good-height adjustment is computed before that second getter, so a getter that changes good height cannot affect the already computed adjustment. Positive keyboard values use `(goodHeight + keyboard) + 15` and still perform the first bottom getter, but not the second.

The nonpositive/unordered keyboard result is `gap + (secondBottom + adjustment) + 15`, with separate additions in this order. Gap is 30 exactly when screen width differs from 375 and the first bottom getter returned zero. `FCMP`/`FCSEL GT` at `0x1bebd0`/`0x1bebd4` selects `goodHeight - 30` only for an ordered positive value; NaN selects zero. The decompiler's `goodHeight <= 0 ? 0 : goodHeight - 30` incorrectly preserves NaN. Keyboard uses ordered `CSET GT` at `0x1beb10`, so NaN takes the nonpositive branch.

Stack handling skips only count 1. For count 0 with the normal NSNotFound index, scale is 0.9. Unsigned last/second-last comparisons retain their original wraparound semantics: a synthetic index UINT_MAX/count0 takes the last-item branch with no offset, while UINT_MAX-1/count0 takes scale0.95 plus offset5. Last items add5 for count2 or10 for count>2; second-last items use scale0.95 and add0 for count2 or5 otherwise. Older items use scale0.9. Bottom is written before top when applying a stack offset.

`updateLayout` preserves the genuine source-view nil guard. It reads frame width, snapshots the iPad flag, calls `isLandscape`, and multiplies the width fraction before calling calculation. Thus changes to frame, orientation, or the iPad ivar during later callbacks do not replace its captured width. The non-alpha configure call receives duration0.5.

The unused `YTLCalculateToastGeometry` pure helper and its result typedef were removed from `PresentationGeometry.h`; that helper could not represent two independently observed bottom getters or intermediate output writes. The unrelated width, pan, image, detent, progress, and icon helpers remain unchanged. Shared geometry tests already call the real ToastView method and have no direct dependency on the removed helper.

Run `python3 recovery/tools/verify_toast_geometry.py`. The complete source compiles against isolated synthetic UIKit boundaries under UBSan. Tests observe getter order and output state at both bottom-offset calls, replace good height during the second getter, check no synchronization, cover empty/single/multiple stacks and exceptional numeric inputs, and mutate frame/iPad state during updateLayout. All tested output pointers address valid local doubles. A newly compiled ARM64 oracle uses scalar FCMP/CSET GT, FCSEL GT, and individual FADD operations rather than executing code from the original binary. Eight independent source regressions must fail; the full iOS class ABI is also checked.

The original pre-fix whole-source executable failed the initial expected getter sequence (`FAIL ... [trace isEqual:expectedTrace]`). Original anti-debug supervisor calls are recorded and omitted. These tests establish source behavior at mocked UI boundaries; they do not claim physical-device rendering or a byte-identical build.
